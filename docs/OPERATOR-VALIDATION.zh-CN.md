# 使用者接入验收清单

v0.1.0 提供通道和内部链路；请用自己的服务完成以下验证。只启用需要的连接器，不必购买全部平台服务。

## 1. 本地基线

按[安装说明](INSTALL.zh-CN.md)启动，确认两个初始化任务成功、监测服务 healthy、管理员可登录。未配置 API 时应显示未配置而不是模拟成功。确认数据和上传在正常重启后保留。

## 2. 模型与监测

按[接入指南](INTEGRATIONS.zh-CN.md)选择明确的 provider 和当前服务商目录中的模型 ID，在运行环境中填写自己的凭据。工作台生成模型与监测侧是两套配置。先设置供应商限额、应用计划权限/预算及请求级付费许可，再解除对应门禁；不要删除门禁代码来让测试通过。

从应用正常入口发起单条任务，保存真实请求标识、回答、来源、用量和费用。检查失败是否如实记录；未配置/鉴权失败不能显示为成功。API 结果不能标成同名消费级网站的网页采样。

## 3. 网页 AI surface（需要时）

使用自己的采集服务、会话及证据存储。按具体站点检查地区/语言、登录状态、提取内容、时间和证据。没有取得有效回答时记录失败/不可用，不填充 API 或 fixture 回答。

## 4. SMTP

配置自己的 SMTP 及发件域名，使用自己可控的测试收件箱。实际测试注册验证码、重置邮件、失效时间和链接域名；HTTP 提交成功不能代替收件箱收到邮件。不要向无关用户发送测试邮件。

## 5. 知识与生成

用少量非敏感测试资料验证录入、切片和检索。没配置 embedding 时是文本检索；配置后核对真实向量维度。生成内容需人工检查事实、引用及禁止公开的信息。

## 6. 发布与复测

使用自己的 WordPress、站点 Agent 或 webhook 测试目标，先验证健康检查和草稿，再发布已审核测试内容。核对接收端记录、实际可访问 URL、标题和正文；仅收到 HTTP 200 不算内容落地成功。

随后使用相同问题集和可比采样条件进行一次复测，保留原始回答与来源。前后差异不自动证明因果或流量增长。

## 7. 完成记录

按“服务/模型或站点、日期、配置版本、请求标识、结果、费用、失败原因”保留脱敏记录。确认通过再启用周期任务。凭据只留在运行环境；向 Issues 报告问题时去除密钥、Cookie、客户资料及日志中的个人信息。
